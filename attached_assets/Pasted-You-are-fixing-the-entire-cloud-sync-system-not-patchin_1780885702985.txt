PHASE 2 — AUTH BOOT ORDER
────────────────────────────────────────

Fix app startup order.

Correct boot sequence:

1. Initialize Supabase client.
2. Restore local app data.
3. Restore Supabase auth session.
4. Wait for auth initialization result.
5. If session exists:
   - verify user.id
   - verify access_token exists
   - optionally refresh session if token is near expiry
   - set sync state to authenticated_ready
6. If no session:
   - set sync state to paused_auth
   - do not upload
   - do not download
   - do not DB-write
7. Only after authenticated_ready, run sync queue.

Wrong behavior to remove:
- Sync starts immediately on app load.
- App redirects logged-in user to auth page before session restoration finishes.
- Upload starts while session is null.
- Auth error causes infinite retry.
- Storage upload runs before user.id exists.
- Queue starts before auth provider finishes loading.

Implement:

CloudSyncBootstrap:
- waits for INITIAL_SESSION / getSession completion
- subscribes to auth changes
- on SIGNED_IN → unlock sync
- on TOKEN_REFRESHED → resume blocked auth queue
- on SIGNED_OUT → pause sync and clear sensitive remote session state
- on USER_UPDATED → revalidate user context

Important:
Use getSession for client-side session restoration, but do not blindly trust stale local session.
Before protected writes, validate user with getUser or ensure Supabase request succeeds using the authenticated client.

PHASE 10 — CONFLICT RESOLUTION
────────────────────────────────────────

Conflict detection:

Compare:
- local updated_at
- remote updated_at
- local version
- remote version
- content_hash
- device_id
- baseVersion

Conflict cases:
1. Local changed, remote unchanged → upload local.
2. Remote changed, local unchanged → download remote.
3. Both changed same fields → conflict.
4. Both changed different mergeable fields → merge.
5. File/blob changed both sides → keep both or ask user.

Resolution strategy:
- For simple records: latest updated_at wins only if safe.
- For study sessions/tasks: merge by id.
- For settings: field-level merge.
- For profile avatar: latest explicit user change wins.
- For backups: never overwrite; create new version.
- For ambiguous conflicts: create conflict copy.

Conflict item naming:
{entity}-{recordId}-conflict-{timestamp}

Log every conflict.

Never silently overwrite newer data.
